# Catalog tools

Пишет инструменты в корневой `README.md`. Каталог на русском. Одна запись — одна строка.

## Вход

Пользователь даёт один или несколько инструментов в любом виде. Типичный вход:

```
Free-coding-models (https://github.com/vava-nessa/free-coding-models) — найдите, протестируйте и установите в CLI более 170 моделей LLM с БЕСПЛАТНЫМ кодированием у более чем 15 поставщиков в режиме реального времени
```

Также нормально: только URL, «название + ссылка», список из чата, несколько штук сразу.

## Формат записи

В `README.md` каждая позиция — пункт списка в **таком виде** (длинное тире `—`):

```
- [Name](https://example.com) — краткое описание
```

- `Name` — имя репозитория или продукта, без лишнего маркетинга в названии
- URL — канонический (без `.git`, без хвостового `/`, `https://`)
- Описание — одно предложение на русском, см. правила ниже

Именно `[Name](url)`, иначе GitHub не делает имя кликабельным. Вход пользователя может быть `Name (url) — …` — это разобрать, в файл писать markdown-ссылку. Описание с новой строки не писать.

## Workflow

1. Прочитать корневой `README.md`. Если файла нет — создать по шаблону из этого скилла, затем писать туда.
2. Разобрать вход: имя, URL, сырое описание. Несколько инструментов — все за один проход.
3. Если нет имени или описания, а есть URL — открыть страницу/репозиторий и восстановить факты. Не выдумывать цифры.
4. Проверить дубликаты: тот же URL (без `/`, `.git`, регистра) или то же имя без учёта регистра. Дубликат — не добавлять, сказать где уже лежит.
5. Выбрать **одну** категорию из таксономии ниже. Предпочитать существующий `##` в README, если он совпадает по смыслу.
6. Доработать описание.
7. Вставить строку в нужную секцию **по алфавиту** имени (без учёта регистра, игнор ведущих символов вроде `awesome-`).
8. Если появился новый `##` — обновить блок «Содержание».
9. В ответе пользователю: что добавлено, в какую категорию, исходник vs итоговая строка. Если описание сильно переписано — одна фраза почему.

Не коммитить, пока пользователь отдельно не попросил.

## Описание

Цель: человек за 3 секунды понимает, **что это и зачем брать**.

- Русский, одно предложение, 80–180 символов. Можно чуть длиннее, если без факта строка слепая.
- После `—` — именная формулировка, не призыв: «каталог …», «CLI для …», не «найдите / протестируйте / установите».
- Без КАПСА, «лучший», «революционный», «must-have», эмодзи, восклицаний.
- Сохранять проверяемые факты: число моделей, провайдеров, платформа (CLI, MCP, IDE).
- Убрать воду: «в режиме реального времени», «более чем», «бесплатно» — только если это главный смысл (например, именно каталог бесплатных моделей).
- Не переводить имя продукта. Можно пояснить англицизм одним русским словом.

**Пример**

Вход:

```
Free-coding-models (https://github.com/vava-nessa/free-coding-models) — найдите, протестируйте и установите в CLI более 170 моделей LLM с БЕСПЛАТНЫМ кодированием у более чем 15 поставщиков в режиме реального времени
```

Итог:

```
- [Free-coding-models](https://github.com/vava-nessa/free-coding-models) — каталог 170+ бесплатных coding-моделей от 15+ провайдеров с установкой в CLI
```

Категория: `Модели и роутинг`.

## Категории

Классификация по работе инструмента, не по вендору. Новую секцию создавать только если ни одна строка не подходит.

| Секция | Кладём сюда |
|---|---|
| Агенты и IDE | Агенты в редакторе, coding assistants, обвязки вокруг Cursor/Claude Code/Continue |
| CLI и терминал | CLI, TUI, установщики в терминал, не каталоги моделей |
| Модели и роутинг | Каталоги моделей, роутеры, гейтвеи, прокси к провайдерам |
| MCP и интеграции | MCP-серверы, коннекторы, мосты к внешним сервисам |
| Память и знания | RAG, вики, память агента, базы знаний |
| Автоматизация | Воркфлоу, cron-агенты, оркестрация, n8n-подобное |
| Дизайн и фронтенд | UI-киты, генерация макетов, фронтенд-утилиты |
| Данные и аналитика | ETL, склад, дашборды, разбор таблиц |
| Качество и безопасность | Эвалы, линтеры, сканеры, тесты агентов |
| Обучение и справочники | Курсы, гайды, awesome-подборки про практику |
| Прочее | Только если иначе никак |

Сомневаешься между двумя — бери ту, где пользователь будет искать инструмент в первый раз. Напиши об альтернативе в ответе, не дублируй запись.

## Правила правки файла

- Менять только нужную секцию и «Содержание», если добавился `##`.
- Не переписывать чужие описания «для красоты», кроме явного запроса «почисти каталог».
- Сохранять уже принятый порядок секций.
- Якоря в содержании — GitHub-slug: кириллица как есть в нижнем регистре, пробелы → `-`.

## Ответ

Коротко:

```
Добавлено в «Модели и роутинг»:
- [Free-coding-models](https://github.com/vava-nessa/free-coding-models) — каталог 170+ бесплатных coding-моделей от 15+ провайдеров с установкой в CLI
```

Если дубликат или не хватает URL — не молчать.
